# Guanche Warriors – Production Plan v0.1

## 1. Production Goal

Create a short, playable vertical slice that demonstrates the main systems of the game without attempting to fully develop or polish every feature.

The project should demonstrate competence across:

- Unity 2D development.
- Player movement and exploration.
- NPC interaction.
- Scene transitions.
- Turn-based combat.
- Character stats and progression.
- Skills and shared resources.
- Transformations.
- Enemy encounters.
- Basic UI.
- Pixel-art integration.
- Basic narrative implementation.

The final result should be presentable enough to communicate the intended experience, while keeping the scope small enough to complete within approximately three months.

## 2. Development Constraints

**Estimated duration:** 3 months

**Estimated weekly dedication:** 9–10 hours

**Approximate total development time:** 110–120 hours

The project prioritizes learning and demonstrating a broad range of game development skills over deeply polishing every individual system.

Core gameplay systems should be designed to remain reusable after the course.

Temporary content, placeholder art and some prototype implementations may be replaced during later personal development.

## 3. First Playable Target

The first playable version should allow the player to:

- Move through an exploration area.
- Interact with an NPC.
- Transition into the spiritual world.
- Encounter visible enemies.
- Enter a separate JRPG-style battle scene.
- Control two playable Warriors.
- Use basic attacks.
- Use Skills.
- Manage the shared Spiritual Pool.
- Exploit elemental weaknesses.
- Build a Transformation Gauge.
- Transform during combat.
- Gain Experience after battle.
- Return to exploration after combat.

The prototype does not require final narrative content or final artwork.

## 4. Development Roadmap

### Phase 1 — Project Foundation
**Weeks 1–2**

Goal: create the basic playable exploration framework.

- Project structure.
- Player movement.
- Collision.
- Basic camera.
- NPC interaction.
- Scene organization.
- Physical / Spiritual world transition prototype.

### Phase 2 — Basic Battle System
**Weeks 3–4**

Goal: complete the minimum turn-based combat loop.

- Battle scene.
- Player and enemy combatants.
- Turn order based on Speed.
- Basic Attack.
- Defend.
- HP and defeat.
- Victory condition.
- Return to exploration.

### Phase 3 — Skills and Resources
**Weeks 5–6**

Goal: introduce the main strategic systems.

- Skills menu.
- Shared Spiritual Pool.
- Skill costs.
- Elemental affinities.
- Weakness / resistance system.
- Critical hits.
- Basic status effects: Poison and Burn.

### Phase 4 — Transformation System
**Weeks 7–8**

Goal: implement the main signature mechanic.

- Individual Transformation Gauge.
- Gauge generation.
- Transformation state.
- Stat bonuses.
- Elemental bonuses.
- Transformation duration.
- Final Technique.
- Spiritual Pool restoration after transformation.

### Phase 5 — Party and Progression
**Weeks 9–10**

Goal: demonstrate character progression and party management.

- Second playable Warrior.
- Two-character party.
- Shared Experience.
- Level progression.
- Basic Skill unlocks.
- Spiritual Energy rewards.
- Simple accessory system.

### Phase 6 — Vertical Slice and Polish
**Weeks 11–12**

Goal: connect all systems into a short presentable experience.

- One small physical-world area.
- One spiritual-world area.
- Several enemy encounters.
- NPC interaction.
- Basic UI polish.
- Placeholder or initial pixel art.
- Audio placeholders.
- Bug fixing.
- Playtesting.
- Build/export.

## 5. Out of Scope for the 3-Month Version

The following features are intentionally excluded unless development progresses significantly faster than expected:

- All eight Warriors.
- Full story.
- Multiple islands.
- World map exploration.
- Spiritual mounts.
- Complete equipment system.
- Multiple armor upgrades.
- Large Skill trees.
- Large enemy bestiary.
- Advanced enemy AI.
- Complex puzzles.
- Full animation sets.
- Final soundtrack.
- Final visual effects.
- Full save system.
- Large number of status effects.
- Timed physical attacks.

## 6. Production Principle

When choosing between depth and breadth during the three-month development period, prioritize completing a simple version of the full gameplay loop.

A working basic implementation is preferred over an advanced but incomplete system.

Features can be expanded after the course as part of the long-term personal project.
